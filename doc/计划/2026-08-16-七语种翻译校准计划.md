# 七语种翻译校准实施计划

## 目标

对 `zh-cn`、`zh-tw`、`ja`、`ko`、`de`、`ru`、`hi` 的 500 个词条逐项校准。英文词条继续作为语义来源；技术标识、代码、API 名称和路径不强行翻译。

## 内容质量约束

- 每个语种由一个独立的 Luna（high）子代理负责，只修改该语种的词条 YAML。
- 删除批量占位文案，定义、机制、价值、项目示例、提示词和常见错误必须分别表达对应含义。
- 标题采用该语言技术社区常用译名；必要时保留英文标准名作为页面既有的对照信息。
- 保持 YAML 结构、`source_content_version` 和真实审校状态；机器校准不能伪装成母语人工审校。
- 公共页面将领域、难度、生命周期等内部 ID 显示为本地化名称；没有别名时不显示空别名字段。

## 实施顺序

1. 增加翻译质量与本地化元数据的失败测试。
2. 分批并行校准七个非英语语种，每个语种一个子代理。
3. 修正公共渲染逻辑与 UI 标签，更新术语表索引。
4. 运行语料、静态构建、JavaScript、真实 HTTP 浏览器和移动端检查。
5. 由独立子代理统一执行一次正式验收；通过后归档本计划及任务验收记录。
6. 合并至 `main`、推送 GitHub，并等待 GitHub Pages 成功后读回关键页面。

## 验收重点

- 七种语言均有 500 个完整词条，且不再出现已知模板占位语句或字段机械重复。
- `Breadcrumb` 等抽样词条采用自然准确的译名，页面不再裸露 `ui-ux`、`beginner`、`design` 等内部 ID。
- 桌面与移动端可见内容完整，搜索、术语卡片、动态示例、小练习和项目路径不回归。
- 发布产物与本地验收提交一致，线上关键路由可访问。
