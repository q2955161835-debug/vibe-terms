## 详细报告

### 验收方法

- 验收时间：`2026-08-16 19:03 ~ 2026-08-16 19:20`。
- 随机种子：`20260816-vibe-terms-<locale>`。每种语言先打乱 12 个领域，依次从前 6 个不同领域随机选一个词条，形成 6 语言 × 6 词条的 36 样本；每个样本阅读标题、简短定义、工作方式和项目示例。
- 额外全覆盖固定词：Breadcrumb、Token、Grounding、Guardrail、Hero、Cookie、Record、Flag、HEAD、Mock、Mockup、Fake、Branch、Component、Staging，6 语言共 90 个 title/short_definition。
- 该策略为用户要求的随机抽查，不等价于 500 词逐条人工审校。

### 验收项 A：翻译准确性与术语保留

步骤：读取 36 个种子样本和 90 个指定高风险字段，检查短字段与长字段的自然度、语义、技术术语保留和英文残留。

预期：本地术语应使用目标语言的常见技术称呼，必要 canonical 英文可保留；不能把 Shell、Canary Release、agent 等技术概念改成日常词义。

实际证据：抽样首轮发现 `de/shell`、`de/canary-release` 与 `ko/multi-agent-system` 各一处错误；修复后重新读取所有 `title`、`short_definition`、`mechanism`、`project_example` 和 `ai_prompt_example`，分别为 Shell、Canary-Release、에이전트。对 `Hülse`、`Kanarische Veröffentlichung`、`상담원` 的运行时源目录检索为 0 命中。高风险词保留其导航、LLM、Git、测试、视觉稿或预生产含义。

结果：通过。

### 验收项 B：共享内容与 Hindi 移除

步骤：运行 `python -m pytest -q tests/test_supported_locales.py tests/test_full_corpus.py tests/test_content_schema.py tests/test_static_site.py tests/test_urls.py` 与 `npm run test:js`；检索运行时内容和配置中的 Hindi。

预期：7 个 locale（en、zh-cn、zh-tw、ja、ko、de、ru）一致覆盖，taxonomy、glossary 和 3 条项目路径没有 Hindi 运行时残留。

实际证据：Python `43 passed`；JavaScript `17/17`。`test_supported_locales.py` 验证未保留 `hi` 词条/路径文件和 taxonomy/glossary 键。Hindi 文本仅在不可执行的历史归档计划与移除记录中存在。

结果：通过。

### 验收项 C：浏览器与静态路径

步骤：使用真实 Playwright CLI 打开根路径及六语种代表页；桌面检查 zh-cn、ja、de、ru，390×844 移动检查 zh-tw、ko；在 `zh-cn/terms/domain/` 顶栏实际搜索并提交；以 `BASE_PATH=/vibe-terms` 重新生成静态站点并验证链接/资源前缀。

预期：搜索、知识地图、项目路径、示例和练习可见；本地标题与 canonical 英文不重复；无页面级横向溢出；根和子路径均无链接泄漏。

实际证据：根页含搜索、12 个知识地图链接和 55 张卡。代表词条均有必要区块，移动样本 `scrollWidth == 390`，控制台 0 error。搜索实际跳转 `/zh-cn/terms/threat-model/`。`BASE_PATH=/vibe-terms` 构建生成 7 语言目录，首页 locale 链接与词条脚本均带前缀，且无未前缀 locale href。

结果：通过。
