# Vibe Terms 500 词可视化解读与暗色主题设计

**日期：** 2026-08-16  
**状态：** 待用户书面复核  
**范围：** 匿名、本地优先、静态站点；不增加账号、数据库或云端运行依赖

## 1. 目标

本阶段为全部 500 个规范术语增加与术语含义相匹配的可视化概念解读，并修复当前暗色主题中顶栏、卡片、图解区和文字对比度失真的问题。

可视化解读参考 VibeHub 的 CSS 词条所采用的产品原则：用具体场景、可见对象、状态切换和结果高亮解释概念，而不是给定义加一张装饰图。不得复制参考站的品牌、原文、代码或具体画面。

交付必须满足：

- 500/500 术语都有独立图解数据，禁止以一个通用四卡模板冒充定制图解；
- 图解复杂度由术语决定，可以是单状态静态解剖，也可以是多状态交互流程；
- 只维护英文和简体中文两套图解文案；
- `zh-cn`、`zh-tw` 使用简体中文图解，其他 locale 使用英文图解；
- 原有定义、四阶段文字说明、小练、项目路径、来源和相关词继续保留；
- 浅色、暗色和跟随系统三种主题均可读、可操作且无横向页面溢出；
- 关闭 JavaScript 后仍能理解图解的主要对象、步骤与结论。

## 2. 非目标

- 不为图解新增第三至第七套翻译；
- 不运行用户代码，不使用 `eval`，不加载第三方 iframe；
- 不把 500 个术语实现成 500 个互不相干的 JavaScript 组件；
- 不使用整页截图或带文字的位图作为主要解释内容；
- 不在本阶段改动账号、同步、分析、支付或提醒功能。

## 3. 已确认问题与设计依据

### 3.1 暗色主题根因

线上只读复现确认：`html[data-theme="dark"]` 已切换为暗色基础变量，但后加载的 `web/clarity.css` 仍对顶栏、术语卡、示例画布和标题使用 `#fff`、`#111...` 等浅色常量，并把 `system` 直接归入浅色规则。结果是暗色页面出现白色顶栏和白色卡片，部分继承文字却保持浅色，形成低对比或不可见控件。

### 3.2 现有示例边界

当前所有词条都有“情境、概念、应用、验证”四阶段文字卡，20 个核心词支持阶段切换。该模块提供了学习摘要，但没有为 CSS、API、数据库、状态、权限等概念建立不同的对象关系和可视结果。

新图解作为现有示例区的增强层：先显示术语专属图解，再保留四阶段文字说明。现有内容不得因加入图解而被删除或隐藏为仅 JavaScript 可见。

## 4. 方案选择

采用“结构化视觉语法 + 少量专用渲染器”。

- 公共视觉语法负责主题、布局、状态、面板、连接关系、键盘交互和响应式行为；
- 每个术语拥有独立的结构数据和中英文文案；
- 大多数术语选择一个公共图解模式并配置自己的对象、状态和结果；
- 只有公共模式无法准确表达的术语才使用白名单专用渲染器；
- 专用渲染器仍必须遵守同一主题变量、状态接口、无障碍和静态回退契约。

该方案在 500 词定制程度、长期维护和静态站点体积之间取得平衡。

## 5. 信息架构与页面顺序

词条页主要顺序调整为：

1. 双语词条身份、用户常见说法和一句话定义；
2. **术语专属可视化解读**；
3. 原有四阶段文字说明；
4. 机制、边界、项目示例与使用场景；
5. 小练、AI 提示词、常见误区、项目路径、相关词和来源。

图解区结构固定为：

- 解释型标题：描述图解要回答的问题，而不是重复术语名；
- 一句话导读：说明用户应观察什么；
- 可选状态控制：只在两个及以上状态时出现；
- 场景画布：展示对象、关系、变化和结果；
- 当前状态结论：明确“发生了什么”和“为什么”；
- 无 JavaScript 文本记录：按顺序列出全部状态及结论。

## 6. 视觉语法

首版支持以下 14 种模式。模式是布局和交互语法，不是通用文案模板。

| 模式 | 适用概念 | 典型对象 |
|---|---|---|
| `anatomy` | 组件、文件、协议组成 | 标注区域、职责、边界 |
| `compare` | 相近概念、正确/错误 | 并列面板、差异高亮 |
| `sequence` | 有明确先后顺序的流程 | 步骤、输入、输出 |
| `state-machine` | 状态、事务、交互状态 | 状态节点、允许转换、当前态 |
| `request-response` | API、HTTP、RPC | 客户端、约定、服务端、响应 |
| `pipeline` | 构建、检索、部署、数据处理 | 多阶段处理器和中间产物 |
| `hierarchy` | DOM、权限、目录、依赖 | 父子层级、继承和作用域 |
| `code-result` | CSS、HTML、查询、配置 | 源片段、规则计算、可见结果 |
| `data-mapping` | Schema、序列化、ORM、键关系 | 字段、映射、存储结果 |
| `lifecycle` | 发布、Token、任务、连接 | 创建、使用、失效、恢复 |
| `boundary` | 安全边界、前后端、隔离 | 可信区、非可信区、检查点 |
| `layout` | 盒模型、Grid、响应式 | 容器、尺寸、断点、溢出 |
| `timeline` | Git、事件、重试、版本 | 时间顺序、分叉、回退点 |
| `evidence` | 测试、日志、监控、验收 | 行为、证据来源、判定结果 |

复杂度不设平均配额：

- `1`：单状态，1–3 个主要对象；
- `2`：2–3 个状态或一组清晰对比；
- `3`：3–5 个状态、多个面板或分支；
- `4`：需要白名单专用渲染器的复合概念。

复杂度只控制数据与交互规模，不改变信息质量门槛。

## 7. 内容数据模型

每个术语新增一个独立文件：

`content/explainers/<term-slug>.yaml`

共同结构如下：

```yaml
schema_version: 1
term: css
pattern: code-result
complexity: 3
copy:
  en:
    heading: How two CSS rules decide the final button color
    intro: Follow the matching rule, winning declaration, and computed result.
    states:
      base:
        label: Base rule
        conclusion: The primary-button declaration currently wins.
    labels:
      source: button.css
      result: Computed
  zh-cn:
    heading: 两条 CSS 规则怎样决定按钮的最终颜色
    intro: 依次观察匹配规则、胜出声明和最终计算结果。
    states:
      base:
        label: 基础规则
        conclusion: 当前由主按钮规则提供最终颜色。
    labels:
      source: button.css
      result: 计算结果
states:
  - id: base
    focus: [primary-rule, computed-value, preview-button]
    values:
      computed-color: "#4338ca"
scene:
  nodes:
    - id: primary-rule
      role: code
      label_key: source
      value: ".primary { background: #4338ca; }"
    - id: computed-value
      role: result
      label_key: result
      value_from: computed-color
  relations: []
```

约束：

- `term` 必须与目录 slug 一致；
- `copy` 只允许且必须包含 `en`、`zh-cn`；
- 两种语言必须拥有相同的状态 ID 和标签 key；
- `pattern` 必须来自注册表；
- `focus`、关系端点和 `value_from` 必须引用存在的 ID；
- 代码、命令、路径、颜色、状态码等非自然语言值放在结构区，避免双份复制；
- 每个文件必须有术语专属标题、导读和状态结论；禁止从通用定义自动回填后直接通过发布门禁。

## 8. 语言回退

图解文案选择器是独立、显式且可测试的纯函数：

| 页面 locale | 图解文案 locale |
|---|---|
| `zh-cn` | `zh-cn` |
| `zh-tw` | `zh-cn` |
| `en` | `en` |
| `ja` | `en` |
| `ko` | `en` |
| `de` | `en` |
| `ru` | `en` |

页面导航、术语定义、小练等原有内容继续使用页面 locale；只有新图解模块按此表回退。渲染后的图解根节点记录 `data-explainer-locale`，便于测试和问题定位，但不显示干扰学习的内部状态标签。

## 9. 渲染与模块边界

新增模块：

- `scripts/vibe_terms/explainers.py`：读取、规范化、交叉引用验证和语言选择；
- `scripts/vibe_terms/explainer_renderers/`：公共模式渲染器与白名单专用渲染器；
- `web/explainers.css`：图解画布、面板、状态与响应式样式；
- `web/explainers.js`：通用状态切换、键盘导航和实时结论更新；
- `content/explainers/`：500 份术语专属结构与中英文内容。

`render.py` 只负责调用统一入口，不承载每种模式的业务细节。`app.js` 不接管图解状态；`examples.js` 保留原有四阶段示例增强，避免两个系统相互耦合。

每个词条页面只内联当前术语的图解 HTML，不下载 500 词的全集。共享 CSS、JavaScript 和图标资源只加载一次。

## 10. 交互契约

- 一个状态：不渲染无意义按钮；
- 多个状态：使用真实 `button`，容器有可读名称，按钮维护 `aria-pressed`；
- 左右方向键在状态按钮间移动，Home/End 跳到首尾；
- 切换状态只改变高亮、可见值和结论，不删除其他状态的文本记录；
- 选中对象使用边框、背景和文字三重信号，不只依赖颜色；
- `prefers-reduced-motion` 下关闭位移和渐变过渡；
- 未注册模式或损坏数据在构建期失败，不在生产页面静默降级为空白。

## 11. 暗色主题设计

建立单一语义变量契约，`styles.css` 定义主题值，`clarity.css` 和 `explainers.css` 只消费变量：

- 画布：`--canvas`、`--canvas-subtle`；
- 面板：`--panel`、`--panel-raised`、`--panel-muted`；
- 文字：`--text-primary`、`--text-secondary`、`--text-faint`；
- 边界：`--border`、`--border-strong`；
- 强调：`--accent`、`--accent-surface`、`--accent-contrast`；
- 反馈：成功、警告、危险和代码语义色；
- 阴影、焦点环和遮罩透明度。

规则：

- `data-theme="light"` 明确使用浅色；
- `data-theme="dark"` 明确使用暗色；
- `data-theme="system"` 只通过 `prefers-color-scheme` 选择两套值，不再默认绑定浅色；
- 组件样式禁止以 `#fff`、`#111` 等常量表达主题表面或文字；非主题数据颜色必须同时声明浅暗可读策略；
- 普通正文对比度目标至少 4.5:1，大字号至少 3:1，焦点和非文字边界至少 3:1；
- 图解中的代码、禁用态、次要标签和未激活面板仍需可辨认，不以极低 opacity 模拟“未激活”。

## 12. 图标与视觉资产

参考页的主要信息由真实 UI 面板和文本组成，不需要为 500 词生成带文字位图。公共角色图标使用本地打包的 Phosphor 图标子集，保持 MIT 许可记录；禁止把 emoji、字符箭头或手写 SVG 当作正式图标。

连接关系由图解渲染器的语义布局表达，装饰性图片不承担关键含义。若后续个别术语确需独立插画，必须作为单独资产经过来源、暗色和替代文本检查，不作为本阶段覆盖门槛。

## 13. 静态回退、性能与安全

- 构建产物直接包含首状态画布、全部状态标题和结论列表；
- JavaScript 失败时首状态仍完整可见；
- 禁止执行 YAML 中的代码字符串；代码仅按文本转义渲染；
- 禁止第三方嵌入和远程运行时依赖；
- 共享图解 CSS 与 JavaScript 各自设置体积门槛，单页只包含当前术语数据；
- 所有 URL 继续通过 `UrlBuilder`，兼容根路径和 `/vibe-terms`；
- 搜索索引不复制完整图解正文，避免 500 词全局载荷膨胀。

## 14. 内容生产与质量门禁

500 词按 12 个领域分批编写，但只做快速自动化检查，不进行每批独立正式验收。全部完成后统一进行一次独立正式验收。

每份图解必须通过：

- 结构与引用验证；
- 中英文 key 对齐；
- 标题、导读、状态结论非空；
- 至少出现一个与该术语独有对象或行为相关的结构值；
- 与同领域其他词的完整状态签名不得机械重复；
- 代码、路径、协议值保持原样；
- 图解结论不得与英文规范定义冲突。

允许共享模式和角色名称，不允许共享整段泛化说明。质量审计输出按领域、模式和复杂度统计，但不强制人为均匀分布。

## 15. 测试与验收

### 自动化测试

1. `500/500` 术语存在图解文件，且没有多余 slug；
2. 14 个公共模式各有结构 fixture 和渲染测试；
3. `en`、`zh-cn` key 完全对齐，locale 回退表逐项断言；
4. 损坏 ID、未知模式、缺失复制、代码未转义必须红灯；
5. 每个生成词条页包含专属画布、静态状态记录、原四阶段示例和小练；
6. 单状态无空控制，多状态可点击并正确维护 ARIA；
7. 根路径与 `/vibe-terms` 的资源和链接一致；
8. 浅色、暗色、系统主题切换与本地偏好恢复通过；
9. CSS 静态审计阻止主题组件重新引入未经豁免的浅色常量；
10. 完整 Python、JavaScript、HTTP E2E、打包和 Sites 构建继续通过。

### 浏览器设计 QA

- 按 14 个模式各抽至少一个代表词，覆盖英文、简中、繁中回退和其他语言英文回退；
- 桌面至少 1280×720，移动端至少 390×844；
- 每种代表模式检查浅色和暗色；
- 检查页级横向溢出、控件可见性、代码换行、焦点、状态切换和控制台；
- 对 CSS 代表页与参考页进行同视口原则对照，只比较信息层级和交互清晰度，不追求品牌像素复制。

### 最终通过标准

- 500 词图解覆盖与双语回退门禁全绿；
- 暗色主题无不可读顶栏、卡片、代码或禁用控件；
- 原有搜索、知识地图、项目路径、四阶段示例、小练和本地进度无回归；
- 独立统一验收结论为“通过”；
- 通过后才合并 `main`、推送并等待 GitHub Pages 成功部署与线上读回。
